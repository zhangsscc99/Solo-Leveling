## 2026-11-15 14:33 UTC

试玩步骤：建档 → 探索前进 ×40+ → 环顾四周 → 潜行 → 休息 → 攻击（无敌人时）→ 背包（装备猎刀 / 喝治疗药水）→ 技能面板（点锁定技能）→ 任务面板 → 地图面板 → 战斗按钮 → 存档 → 自由行动（3 次不同意图）→ 移动端/桌面布局测量。

**结论：主流程在第一步之后就断了。** 唯一的推进动词「探索前进」是写死的静态模板，场景与章节永不变化；AI 叙事层实际处于 degraded 占位态；战斗面板常驻但按钮全为死键。玩家最多能把 HP 从 100 点到 1（点不下去也死不了），除此之外游戏没有任何状态推进。

### 1. 「探索前进」是死循环模板，场景/章节永不推进 — blocker

- **现象**：连续点击「探索前进」40 余次，日志文本逐字相同：`你踩着碎石向那扇石门挪去，脚下的石砖忽然下沉半寸……（体力消耗 HP 100→97 · MP 20→18）`，只有数字在变。章节一直停在 `第1章 双重地下城`，任务面板主线恒为 `0/9`，地图里 `Ch.2 每日任务` 永久 `未解锁` 且不给任何解锁条件。全流程从未出现过怪物、从未进入战斗、从未换过场景。
- **复现步骤**：
  1. 打开 https://openfolio.uk/game，输入代号点「觉醒」；
  2. 连点「探索前进 1」10 次，观察日志区（可复制文本对比，除 HP/MP 数字外完全一致）；
  3. 点「任务 9」→ 主线「第1章 · 双重地下城」进度仍 `0/9`；
  4. 点「地图 8」→ `Ch.2` 起全部 `未解锁`，无解锁条件文案。
- **期望**：每次推进应把 `chapters.json` 里 `scenes[]` 的场景指针前移（该章有 3+ 个 scene 与 `choices{next}` 分支），日志换成新场景文本；第 9 次推进结算主线并 `chapter+1` 解锁第 2 章；无可推进内容时明确提示「此处已无可探索之物」，而不是重复同一段。
- **根因（已定位，仅记录不改）**：`server/index.js` 的 `advance` 意图分支只做 `patch: {hp-3, mp-2}` + 拼一段静态字符串，完全不动 scene/chapter；`chapters.js` 的场景数据没有被运行时消费。
- **严重度**：blocker

### 2. AI 叙事层实为占位回应，自由行动不改变状态 — blocker

- **现象**：自由行动框输入「我举刀砍向那座微笑的石像」并回车，系统播报原文：
  `指令已接收：「我举刀砍向那座微笑的石像」。命运之线仍在编织中……（叙事引擎尚未接入，此处为占位回应。输入「帮助」查看当前可用指令。）`——页面自己承认叙事引擎未接入。同一句话走 API 复核：`POST /game/api/ai-action {"save_id":78,"input":"我举刀砍向石像"}` 返回 `"intent":"observe"`、`"degraded":true`，回复是「环顾四周」的文本。另一次输入「我拔出猎刀走向石像，砍向它的手臂」则因为命中 `/走/` 被规则引擎判成 `advance`，回了一段「踩着碎石向石门挪去」——与玩家输入语义相反。
- **复现步骤**：
  1. 在「做点别的……（自由行动）」里输入任意攻击类描述（如「我举刀砍向石像」）后点 ↵ Enter；
  2. 看蓝色系统播报：出现「叙事引擎尚未接入，此处为占位回应」；
  3. 对比输入「我走向石门」——被当成「前进」并扣 HP/MP。
- **期望**：AI 正常时自由输入应产生对应叙述并推进世界状态；降级时也应由规则引擎给出**与意图一致**的分支（攻击→战斗、观察→环顾），而不是占位文案；前端应显式标注「叙事引擎降级」而不是让玩家以为在玩 AI 剧情。
- **严重度**：blocker（与 F021/F024 已勾选状态矛盾，属实现未落地的功能缺失）

### 3. 非战斗时战斗面板常驻，攻击/技能/防御/道具/逃跑 全是死键 — major

- **现象**：进入游戏第一屏（仍在读开场白、无任何交谈对象）战斗面板就以 `交战 / 回合 — / VS 未知的敌人 Lv.?? HP ??/??` 常驻显示。点「攻击」——日志无新增、无 toast、无 console 报错、HP 不变，静默无响应；「防御」「道具」「逃跑」同样。"战斗"系统按钮点了也没有任何变化。
- **复现步骤**：建档进入主界面 → 不做任何操作直接点面板内「攻击」→ 观察日志与播报区（无变化）→ 再点「逃跑」（同样无变化）。
- **期望**：`section.combat` 只在 `state.combat` 存在时渲染；无战斗时战斗按钮 disabled 并提示「当前没有敌人」；至少给一次失败反馈，不能静默吞掉点击。
- **严重度**：major

### 4. HP 被夹在 1，死亡/复活不可达，且输出虚构的消耗文案 — major

- **现象**：连点探索把 HP 从 100 压到 1 后不再下降（`clamp(save.hp - 3, 1, max_hp)`），永不归零，所以死亡、复活、第 1 章「濒死觉醒」全流程都不可达。更糟的是 HP=1、MP=0 时日志仍写 `（体力消耗 HP 1→1 · MP 0→0）`——没有消耗却宣称消耗；MP 归零后「探索前进」照样能点、照样扣 0，资源门槛形同虚设。
- **复现步骤**：连点「探索前进」约 34 次 → 观察 HP 停在 `1/100`；继续点 5 次，日志每次都是 `HP 1→1 · MP 0→0`。
- **期望**：HP 扣到 ≤0 时进入死亡/复活（或濒死觉醒）分支并写入日志；资源不足时阻断行动并提示「体力不足，需要休息」；文案只描述真实发生的数值变化。
- **严重度**：major

### 5. 主线进度与探索完全脱钩、地图无场景节点 — major

- **现象**：探索 40+ 次后，任务面板主线仍是 `0/9`（计数不随任何行动增长）；地图面板只有 8 个章节名 + `当前位置/未解锁`，**没有任何场景节点**，与 F007「8 章列表、场景节点、当前位置高亮」不符。玩家看不到"离第 2 章还差什么"。
- **复现步骤**：点「任务 9」看主线 `0/9` → 点「地图 8」看章节列表 → 找不到当前场景在章内的位置，也没有进入下一章的操作或条件。
- **期望**：主线计数由实际场景推进驱动；地图展示当前章的场景节点链与高亮位置；未解锁章节给出「需完成第1章主线 9/9」这类条件文案。
- **严重度**：major

### 6. 等级锁定的技能「释放」按钮可点且静默无效 — minor

- **现象**：技能面板里 `Lv.3/Lv.6/Lv.12/Lv.20 解锁` 的 4 个技能，`释放` 按钮 `disabled=false`、`aria-disabled=false`，点击后无请求、无提示、无日志，只在按钮旁有一行灰字「Lv.3 解锁」。

- **期望**：未解锁技能按钮 disabled，点击（或悬停）提示「等级不足：需 Lv.3」。
- **严重度**：minor

### 7. 面板最后一张卡片仍被硬切（已知问题未修） — minor

- **期望**：滚动到底时最后一张卡片与容器底边保留 ≥12px 留白。

## 方向建议

- **玩法不闭环（risk: high，需人工确认）**：现在的"游戏"只有 4 个固定动作 + 1 个死模板推进，`chapters.json` 里已经写好的 8 章 3+ 场景与 choices 分支完全没被运行时使用。建议把「场景节点机」作为第一优先级：`explore` 推进 `sceneIndex` → 场景进入时触发 `encounter` → 战斗由场景触发而不是常驻面板 → 战斗结束回到场景机 → 主线按到达节点计数。这一条不通，后面所有章节内容都是死的。
- **重心不对（risk: high）**：F021/F024/F042/F043/F060–F070 全部标了已完成，但线上体验是"第一章原地踏步 + AI 占位回复 + 战斗按钮无反应"。断言脚本验的是 JSON 内容存在性（`chapter.mjs` 只查关键字），没有一条验"推进 9 次能进第 2 章"或"攻击意图真的进战斗"。建议补端到端断言（场景推进、章节门、战斗进入、死亡复活），把"数据存在"和"玩家能玩到"分开考核。

### 1. 每日「今日狩猎」按输入关键词计数：对空气「攻击」×3 即完成，kills 恒为 0 — major

- **现象**：新档 #114（HP 100/100、MP 20/20、无任何敌人），连点战斗面板「攻击」3 次。每次都只得到系统占位句「指令已接收：「攻击」。命运之线仍在编织中……（叙事引擎尚未接入，此处为占位回应。）」，无回合、无伤害、无敌人出现。但任务面板「今日狩猎」从 `0/3` → `3/3 已完成`，播报「奖励已入账 XP +30 · 金币 +20」；`GET /game/api/saves/114` 显示 `kills: 0`、`hp: 100`、`mp: 20`、`xp: 30`、`gold: 20`。即：**没有击杀任何敌人，击杀任务却完成了。**
- **复现步骤**：
  1. 打开 https://openfolio.uk/game 新建代号 → 进入游戏（战斗面板默认已开）；
  2. 点面板内「攻击」3 次，每次等播报结束；
  3. 点「任务 9」→ 今日狩猎 `3/3 已完成`；
  4. `curl https://openfolio.uk/game/api/saves/<id>` → `kills: 0`、`xp: 30`、`gold: 20`。
- **期望**：击杀计数只由真实战斗结算产生（敌人 HP 归零 → kill 事件）；无敌人时「攻击」应提示「当前没有敌人」且不推进任何任务。任务进度不可由输入文本正则驱动。
- **修复方向**：`server/index.js` 的 `settleDailyQuests(saveId, input)` 现在内部调用 `questEngine.detectEvents(input)`，`/攻击|击败|击杀/` 直接命中 `kill` 事件。应改为由 `resolveAction` / 战斗结算返回 `events`（仅战斗胜利分支产出 `kill`），`detectEvents` 只保留给意图路由，不得直接写每日进度。补一条测试：空挥 3 次后 `daily_hunt.progress === 0`。
- **严重度**：major

### 2. 「释放技能」不扣 MP、无效果，却完成每日「力量校准」并发放奖励 — major

- **现象**：Lv.1 存档 #114 打开「技能 6」→「猛虎猛击」（标注 `MP 12`）→「释放」。回复仍是「叙事引擎尚未接入」占位句，顶部 MP 保持 `20/20`（面板也仍写 20/20），技能没有冷却、没有伤害、没有日志。但「力量校准」从 `0/2` 涨到 `2/2 已完成`，奖励 `XP +20 · 金币 +15` 到账（XP 30→60）。同一缺陷在战斗面板的「技能 → 释放」路径也能复现。
- **复现步骤**：新档 → 技能面板 → 猛虎猛击「释放」×2 → 任务面板显示 `2/2 已完成`；观察 MP 始终 `20/20`。
- **期望**：技能释放必须走真实结算（扣 MP、进入冷却、产生伤害/效果并写日志）；结算未接入前不得推进每日计数，按钮应禁用并注明「技能系统未开放」。
- **修复方向**：与上一条同源——把 `skill` 事件从真实技能结算分支产出；`settleDailyQuests` 不再读输入文本。顺带把 `intentRules` 的「释放技能 X」从占位分支接到 `engine/combat.js`（已有 `SKILLS` 与 `mp_cost/cooldown/power` 数据）。
- **严重度**：major

### 3. 首日经验上限 60 < 升级所需 70：升级、属性点、技能解锁全部不可达 — major

- **现象**：存档 #114 把当天三条每日全部做完（狩猎 30 + 技能 20 + 推进 10 = 60 XP）后，`GET /game/api/saves/114` 为 `xp: 60, level: 1, free_points: 0, xp_to_next: 70`；属性面板显示「经验值 85% 60/70 · 距离 Lv.2 还需 10 经验」「剩余属性点 0」。此时页面内**没有任何还能获得 XP 的动作**：击杀不可达（见旧 F075/F076）、主线 `0/9` 不结算、每日任务已 done，只能等次日 04:00 UTC 重置。也就是说首日永远到不了 Lv.2，`Lv.3/Lv.6/...` 技能与加点系统在首个自然日内全部是死的。
- **补充（代码检索，未在页面跨线验证）**：`server/engine/progression.js` 导出了 `applyXp`，但全仓库没有任何调用点；任务奖励与战斗奖励都只 `updateSave({xp})`，等级不会因 XP 达标而上升。即便第二天 XP 超过 70，也大概率停在 Lv.1。
- **复现步骤**：新档 → 攻击 ×3 + 释放技能 ×2 + 前进 ×1（三条每日完成）→ 属性面板：`60/70`、Lv.1、剩余属性点 0；再点任何动作都不再涨 XP。
- **期望**：XP 达到 `xp_to_next` 时立即结算升级（level+1、max_hp/max_mp 成长、free_points +N、日志播报），并让当日存在 ≥70 XP 的可玩来源（例如首杀 20 XP / 主线节点奖励）。
- **修复方向**：任务与战斗结算后统一调用 `progression.applyXp` 并落库 `level/free_points/max_hp/max_mp`；把「升级」纳入 E2E（新档 10 步内必须到 Lv.2）。
- **严重度**：major

### 4. 装备加成在属性面板与状态栏完全不可见 — minor

- **现象**：存档 #113 在背包装备「生锈猎刀」后，背包槽显示 `武器 生锈猎刀 +4 · 合计 攻 4 · 防 0`，日志写「当前攻击 +4 · 防御 +0」；但「属性 7」面板只有力量/敏捷/体力/智力/感知与经验值，没有攻击/防御/战力；顶部状态栏只有五项属性、金币、XP；输入「状态」也只回五项属性。玩家无法核对装备是否真的生效，战斗里的伤害也无从解释。
- **复现步骤**：背包 → 武器 → 装备生锈猎刀 → 打开属性面板 / 输入「状态」→ 找不到「攻击 4」。
- **期望**：属性面板增加「攻击 / 防御（含装备加成）」两行，或状态栏显示 ATK/DEF，且与背包合计一致。
- **严重度**：minor

### 5. 刷新后日志静默截断为最近 50 条，开场白与早期关键播报无法回看 — minor

- **现象**：存档 #113 刷新前日志区有 59 条，刷新后只剩 50 条，首条从开场白「黑暗散去，你发现自己躺在冰冷的石板上……」变成「HP 100→97」；`GET /game/api/saves/113/log?limit=200` 实际返回 109 条，说明服务端有全量数据，是前端固定只取 50 条且没有「加载更早」。长局玩家会永久丢失开场叙事与升级/任务完成播报。
- **复现步骤**：连续操作 60+ 次 → F5 刷新 → 对比首条日志与 `/api/saves/113/log?limit=200`。
- **期望**：日志分页/「加载更早」按钮，或按需拉取全量并虚拟滚动；至少保留开场与任务关键节点。
- **严重度**：minor
